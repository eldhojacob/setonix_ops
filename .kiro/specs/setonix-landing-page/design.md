# Design Document

## Overview

The Setonix Technologies landing page is a single-page, scrollable marketing site that
reproduces the provided design poster. It is a **fully static site** — HTML, a Tailwind-
compiled stylesheet, vanilla JavaScript, and images — hosted on **GitHub Pages**. There is
no server-side runtime. All interactivity is vanilla JavaScript: smooth-scroll navigation,
a mobile menu toggle, scroll-reveal animations via IntersectionObserver, a hero load-in
fade, and client-side contact-form validation. The contact form submits to a third-party
form service (**Formspree**), so messages are delivered by email without a backend.

The emphasis is on a premium feel: a gentle fade-in on first load and fade-and-rise
reveals as sections enter the viewport, all built on the poster's blue/teal gradient
aesthetic with rounded cards and soft shadows.

### Technology choices

- **Static hosting on GitHub Pages**: the repository serves `index.html` and assets
  directly. No server runs. Assets use relative paths so the site works under a
  project-pages subpath (`https://<user>.github.io/<repo>/`). A `.nojekyll` file disables
  Jekyll processing.
- **Tailwind CSS (CLI build, local only)**: compiled from `src/styles/input.css` to
  `css/styles.css`. Node.js is a **build-time tool only** — it compiles the CSS; it is not
  needed at runtime. The compiled CSS is committed so GitHub Pages serves it as-is.
  Brand palette and gradients are configured in `tailwind.config.js`.
- **Contact form via Formspree**: the `<form>` posts (via `fetch`) to a configurable
  Formspree endpoint. A single placeholder constant holds the endpoint URL; until it is
  set, the form falls back to a `mailto:` link.
- **Vanilla JS**: IntersectionObserver for reveals, no animation library. Honors
  `prefers-reduced-motion`.
- **Semantic HTML**: one `index.html` with clearly delimited `<section>` blocks matching
  the poster order.

## Architecture

```
Build (local, one time / on change):
  Tailwind CLI: src/styles/input.css ──tailwind──▶ css/styles.css   (committed)

Runtime (GitHub Pages — static only):
  Browser ── GET ──▶ GitHub Pages
     index.html + css/styles.css + js/main.js + images/*

Contact form (no backend):
  Browser ── POST (fetch) ──▶ Formspree endpoint ──▶ email to site owner
```

### Project structure

GitHub Pages serves from the repository root, so the publishable site files live at the
root alongside the build tooling.

```
Sentonix/
├── index.html                # full single-page markup (served by GitHub Pages)
├── css/
│   └── styles.css            # generated by Tailwind — COMMITTED (served as-is)
├── js/
│   └── main.js               # nav, mobile menu, reveals, hero fade, form

├── package.json              # scripts: build:css, watch:css (local build only)
```

Note: unlike the previous server-based layout, assets live at the repo root (not under
`public/`) and all asset references in `index.html` use **relative paths** (`css/...`,
`js/...`, `images/...`) so the site works under the GitHub project-pages subpath.

## Components and Interfaces

### Contact form delivery (Formspree)

There is no backend. The contact form is delivered by Formspree, a free form-to-email
service that accepts cross-origin `fetch`/`POST` and emails submissions to the site owner.

- A single constant `FORMSPREE_ENDPOINT` in `js/main.js` holds the endpoint URL
  (e.g. `https://formspree.io/f/XXXXXXX`). The owner creates a free form at formspree.io
  and pastes the id.
- On submit, after client validation, the page sends:

```
POST https://formspree.io/f/XXXXXXX
Headers:  Accept: application/json
Body:     FormData or JSON { name, email, message }
Response: 200 { "ok": true } on success; non-2xx on error
```

- **Graceful fallback**: if `FORMSPREE_ENDPOINT` still contains the placeholder
  (`XXXXXXX`), the submit handler instead opens a prefilled `mailto:info@setonixtech.com`
  link, so the site is usable before Formspree is configured. The form markup also sets
  `action="mailto:..."` as a no-JS fallback.

### GitHub Pages deployment

- Enable Pages in repo Settings → Pages → Source: `main` branch, root folder.
- `.nojekyll` at the root prevents Jekyll from ignoring files/folders that begin with `_`
  and ensures all assets are served verbatim.
- The compiled `css/styles.css` is committed (GitHub Pages does not run `npm`), so the
  live site needs no build.
- Published URL: `https://<username>.github.io/<repository>/`. All asset paths are
  relative so they resolve correctly under the `/<repository>/` subpath.
- README documents: `npm install` → `npm run build:css` → commit → push → enable Pages.

### Markup (`index.html`)

A single document composed of these ordered regions, each a `<section>` with an `id` used
by nav anchors:

1. `header` (fixed nav) — logo, links (`#technology`, `#research`, `#pipeline`, `#about`,
   `#contact`), "Partner With Us" button, mobile hamburger.
2. `#hero` — eyebrow, headline with gradient-accented span, subheading, two CTAs, three
   inline highlights, hero imagery with caption.
3. `#highlights` — three value cards (Mechanical Performance, Bioactive Integration,
   Clinical Adaptability).
4. `#technology` — Technology Platform: heading, paragraph, four capability items,
   composite imagery, caption, horizontal feature strip.
5. `#research` — Research & Validation: heading, paragraph, "Learn More", three cards
   (Laboratory Testing, In Vitro Studies, Preclinical Evaluation), lab imagery.
6. `#pipeline` — Development Pipeline: heading, paragraph, "View Our Pipeline", four
   stages with connecting arrows, caption.
7. `#about` — About Setonix: heading, paragraph, "Learn More About Us", landscape image
   panel, Collaborate/Partner gradient panel.
8. `#contact` — Get in Touch: form (Name, Email, Message, Send Message) + contact details.
9. `footer` — logo, nav links, tagline, copyright.

Reveal-eligible elements carry a `data-reveal` attribute (and optional
`data-reveal-delay` for staggering).

Brand palette (approximated from the poster) defined under `theme.extend.colors`:

```

  100: #d9ecff,
  300: #7cc3f0,   // light sky
  400: #4aa8e6,
  500: #2d8fd6,   // primary blue
  600: #1f6fb2,
  700: #184f86,   // deep navy-blue (headlines)
}
teal: {
  300: #5fd3d0,
  400: #35bdc0,   // accent teal
  500: #15a7ab,
}
```

Gradients (as reusable utility classes in `input.css` `@layer utilities`):
- `.bg-hero-gradient` — diagonal blue→teal wash for the hero.
- `.bg-brand-gradient` — blue→teal for buttons and the Collaborate panel.
- `.text-gradient` — gradient-clipped text for the "Future of Orthopaedics" accent.

Reusable component classes in `@layer components`:
- `.btn-primary`, `.btn-secondary` — pill buttons.
- `.card` — white rounded card with soft shadow and subtle border.
- `.eyebrow` — small uppercase tracked label.
- `.section` — vertical padding + max-width container wrapper.

Typography: a clean sans-serif (system stack or Inter via `@fontsource`/CDN). Headings use
`brand-700`; the hero accent uses `.text-gradient`.

### Behavior (`js/main.js`)

Modules (plain functions wired on `DOMContentLoaded`):

1. **Hero load-in fade**: add a `is-loaded` class to `<body>` (or hero) after first paint;
   CSS transitions hero children from `opacity:0; translateY(12px)` to visible over
   ~0.8s. Skipped under `prefers-reduced-motion`.
2. **Scroll reveal**: `IntersectionObserver` watches all `[data-reveal]` elements; on
   intersect (threshold ~0.15) it adds `is-visible` and unobserves (reveal once). Optional
   per-element delay via `data-reveal-delay` mapped to a transition-delay. Under
   `prefers-reduced-motion`, immediately mark all visible and skip observing.
3. **Smooth scroll nav**: intercept clicks on anchor links to in-page ids; use
   `scrollIntoView({ behavior: 'smooth' })` with an offset for the fixed header.
4. **Mobile menu**: hamburger toggles an `aria-expanded` state and shows/hides the menu
   panel.
5. **Sticky header style**: on scroll past a threshold, add a `scrolled` class
   (background/shadow) to the header for contrast over content.
6. **Contact form**: on submit, prevent default, validate fields (non-empty name/message,
   email regex), show inline errors or a success message. If `FORMSPREE_ENDPOINT` is
   configured, `fetch(FORMSPREE_ENDPOINT, POST)` with `Accept: application/json` and show
   success on a 2xx response (or an error with retry otherwise). If the endpoint is still
   the placeholder, open a prefilled `mailto:info@setonixtech.com` instead.

### Reveal CSS pattern

```css
[data-reveal] {
  opacity: 0;
  transform: translateY(24px);
  transition: opacity .6s ease-out, transform .6s ease-out;
}
[data-reveal].is-visible { opacity: 1; transform: none; }

@media (prefers-reduced-motion: reduce) {
  [data-reveal] { opacity: 1; transform: none; transition: none; }
}
```

## Data Models

Only one transient model — the contact submission:

```
ContactMessage {
  name: string      // required, 1–100 chars
  email: string     // required, matches basic email regex
  message: string   // required, 1–2000 chars
}
```

No database and no backend. The form is validated client-side and submitted to Formspree,
which handles delivery; nothing is persisted in this project.

## Assets

The poster imagery (hero implant with foam, microscopy composites, lab bench, pipeline
cells, mountain landscape, logo mark) will be represented with placeholder images stored
in `images/`. Each is referenced with descriptive `alt` text. Where a licensed exact asset
is unavailable, a visually consistent placeholder (gradient blocks or free stock-style
images) is used so the layout matches the poster's composition; swapping in final brand
assets later is a drop-in replacement by filename.

## Error Handling

- **Contact form (client)**: inline validation messages per field; submit disabled until
  valid; network failure (Formspree unreachable) shows a non-blocking error message with
  retry.
- **Formspree configuration**: if the endpoint is unset (placeholder), the handler falls
  back to a `mailto:` link so the form is never a dead end.
- **Missing images**: `alt` text ensures meaning is preserved; CSS background gradients
  provide a graceful fallback for decorative imagery.
- **Reduced motion**: all animations degrade to immediate visibility.

## Testing Strategy

Given the scope (static marketing page), testing is lightweight and primarily manual:

1. **Build verification**: `npm install` succeeds; `npm run build:css` produces
   `css/styles.css`; opening `index.html` (or serving the folder statically) renders the
   full page with styles applied.
2. **Form behavior check**: with the placeholder endpoint, submitting opens a prefilled
   `mailto:`; with a real Formspree endpoint, a valid submission returns 2xx and shows the
   success message. Invalid input shows validation and does not submit.
3. **Visual/manual QA against the poster**:
   - Section order and content match the poster.
   - Hero fades in on load.
   - Sections fade/rise on scroll; already-revealed sections stay visible on scroll-up.
   - Nav links smooth-scroll to the correct sections; sticky header behaves.
   - Mobile menu toggles; layout reflows with no horizontal overflow at 375px, 768px,
     1280px.
   - `prefers-reduced-motion` disables animations.
   - Keyboard focus is visible on all interactive elements.
4. **Deployment check**: after pushing and enabling GitHub Pages, the published URL renders
   identically to local, with all CSS, JS, and images loading over the project subpath
   (relative paths resolve correctly) and `.nojekyll` present.
